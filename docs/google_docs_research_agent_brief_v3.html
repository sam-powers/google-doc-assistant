@claude in Google Docs comments v1

A Google Docs add-on with a sidebar that processes @claude-tagged comments on demand — no polling, no server.

Stack Google Apps Script
APIs Google Docs, Anthropic
Auth OAuth 2.0 (Google) + Anthropic API key
Trigger Manual — sidebar button
Goal

Build a Google Docs add-on that lets you tag comments with @claude to invoke Claude on highlighted text. Claude can help with anything — research, rewrites, edits, translation, brainstorming — driven entirely by the free-form prompt. A sidebar panel lists all pending @claude invocations. You hit "Run" per comment or "Run all" to process them. Claude replies inline in the comment thread.

Threads are conversational — you can follow up by replying with another @claude tag and Claude will see the full thread history before responding.

No background polling. No server. You control when Claude runs.

User flow

1. Highlight text in the doc, leave a comment with a prompt tagged @claude.

2. Open the add-on sidebar (Extensions > Claude > Open sidebar).

3. Sidebar shows all pending @claude invocations — both new comment threads and follow-up replies in existing threads.

4. Click "Run" on one or "Run all" to process all at once.

5. Claude replies to each comment thread. You can continue the conversation by replying with @claude again.

Trigger rules

A comment or reply queues Claude if and only if it contains @claude and has not yet received a Claude reply after it. Specifically:

— A new top-level comment containing @claude → queued.
— A reply in an existing thread containing @claude → queued.
— A reply in an existing thread that does NOT contain @claude → ignored.

Strip @claude from the prompt text before passing to the model.

Thread context

When processing any invocation, fetch the full comment thread in order and reconstruct it as a message history. Map it as follows:

— User comments and replies (with or without @claude) → role: "user"
— Claude's previous replies → role: "assistant"

Pass the full thread as the messages array. This gives Claude the full conversation context before generating its next reply.

Identify Claude's previous replies by the service account email used to post them (store this as a script property).

Document context

Before firing any jobs, fetch the full document body text. Pass the first ~2000 words to a fast summarization call (use claude-haiku-4-5) and include that summary in every API call as part of the system prompt.

If the doc is under ~500 words, skip summarization and pass the full text directly. Cache the summary for the duration of the sidebar session — don't re-summarize on every "Run" click.

Anthropic API call

Use claude-sonnet-4-5 with web search available. Claude decides whether to use it based on the prompt — no need to enforce it. System prompt establishes context; messages are the reconstructed thread.

{
  model: "claude-sonnet-4-5",
  max_tokens: 1024,
  tools: [{ type: "web_search_20250305", name: "web_search" }],
  system: `You are an assistant embedded in a Google Doc.
The user has highlighted text and left a prompt in a comment.
Help with whatever they ask — research, editing, rewriting,
brainstorming, etc. Be concise. If you search the web,
include sources at the end of your reply.

Document summary: "${docSummary}"
Highlighted text: "${anchorText}"`,
  messages: threadHistory
}
Sidebar UI

For each pending @claude invocation show: the anchor text (truncated to ~60 chars), the latest prompt, and a "Run" button. Plus a "Run all" button at the top. Show a loading state per item while in flight. On completion show "Done."

If nothing is pending, show: "No pending @claude comments."

Reply format

Post reply via documents.comments.replies.create. No rigid template — Claude replies naturally based on the prompt. If web search was used, append a sources section.

Deduplication

A comment or reply is considered processed once Claude has posted a reply immediately after it in the thread. Use the service account email to identify Claude's replies. Store processed comment+reply IDs in PropertiesService as a fallback.

Configuration

Store the Anthropic API key and the service account email in Apps Script script properties. Add a settings panel in the sidebar for first-run setup.

Out of scope for v1

Automatic trigger on comment add (planned for v2 via Cloudflare Worker + Drive push notifications), @claude in Sheets or Slides, per-document configuration.

v2 note

Replace the manual sidebar trigger with a Cloudflare Worker receiving Google Drive push notification webhooks. On comment or reply add, the worker checks for @claude and fires automatically. No polling required.

Deliverables

A working Apps Script project deployable as a Docs add-on. README covering OAuth consent screen setup, script properties configuration, and installation instructions.
